# Matplotlib GUI Compare — Tkinter · PyQt6 · wxPython

Три самостоятельных Python-приложения с **идентичным функционалом** на трёх разных
GUI-библиотеках. Каждое рисует математические графики через Matplotlib внутри
жёстко ограниченной рамки, показывает потребление памяти процесса и системной RAM
и по окончании сессии печатает отчёт о дефектах за период работы (по умолчанию —
часовой прогон).

```
Tkinter + FigureCanvasTkAgg   ─┐
PyQt6   + FigureCanvasQTAgg    ├─ один и тот же контроллер сессии, одинаковые данные и оформление
wxPython+ FigureCanvasWxAgg   ─┘
```

**С чего начать чтение кода:** [`ARCHITECTURE.md`](ARCHITECTURE.md) — карта
«файл → за что отвечает», путь одного кадра и таблица «хочу изменить X → иди в Y».
В каждом модуле первая строка-шапка повторяет роль файла и его связи.

## 1. Что умеет каждое окно

| Блок | Содержимое |
|---|---|
| **Область графика** | Canvas в рамке 1 px. Линия не выходит за рамку ни при каком зуме (см. §4). |
| **График** | Выпадающий список `Random / Meander / Saw` + кнопка **«Показать график»**. |
| **Масштаб** | **Zoom In**, **Zoom Out**, **Сброс**, плюс колесо мыши над графиком. |
| **Память процесса** | RSS, Δ с начала сессии, тренд в МБ/час, число потоков. |
| **Системная RAM** | Занято %, доступно ГБ, полоса заполнения. |
| **Сессия** | Время работы, число перерисовок, время последнего кадра, счётчик нарушений клиппинга. |
| **Стресс-тест** | Флажок авто-перерисовки (кадр каждые 500 мс по умолчанию) — для часового прогона. |
| **Диагностика** | Журнал событий + кнопка **«Сформировать отчёт»**: полный текст с дефектами и вердиктом. |

Метрики обновляются раз в секунду; отчёт дополнительно печатается в консоль при
закрытии окна и сохраняется в `logs/`.

## 2. Установка

```powershell
python -m pip install -r requirements.txt
```

Одной строкой (то же самое):

```powershell
python -m pip install numpy matplotlib psutil PyQt6 wxPython
```

`tkinter` входит в стандартную поставку Python с [python.org](https://www.python.org/downloads/)
для Windows/macOS. В «урезанных» портативных сборках (в том числе в служебном
Python Accio Work) Tcl/Tk может отсутствовать — тогда Tkinter-вариант и
GUI-лаунчер сообщат об этом, а CLI продолжит работать:

```powershell
# поставить полноценный Python (в нём есть tkinter), затем выбрать его в VS Code
winget install Python.Python.3.12

# либо просто пользоваться двумя другими приложениями
python run.py --app qt
python run.py --app wx
```

Проверка, что всё на месте:

```powershell
python -c "import numpy, matplotlib, psutil, PyQt6, wx; print('ok')"
```

## 3. Запуск

```powershell
# Лаунчер: выбрать библиотеку, запустить все три, собрать сравнение
python run.py

# По отдельности (каждое — отдельный процесс со своим event loop)
python -m gcompare.apps.tk_app
python -m gcompare.apps.qt_app
python -m gcompare.apps.wx_app

# Часовой тест памяти: автостоп через 3600 с + авто-перерисовка
python run.py --app qt --duration 3600 --stress
python run.py --app all --duration 3600 --stress --stress-interval 500

# Сводная таблица по трём последним сессиям
python run.py --compare
```

Если `python run.py` в PowerShell падает с «Сбой выполнения программы python.exe»
(`ApplicationFailedException`), значит в PATH стоит нерабочая заглушка
Microsoft Store или Python вообще не прописан в PATH. Обход — файл `start.cmd`
(двойной клик или `start.cmd --app qt --duration 3600 --stress`): он сам находит
рабочий интерпретатор в порядке `.venv` → python.org → PATH → служебный Python
Accio и передаёт ему аргументы.

Параметры CLI (одинаковые у всех трёх приложений):

| Флаг | Смысл | По умолчанию |
|---|---|---|
| `--points N` | точек на кадр | 4096 |
| `--interval MS` | период замера памяти | 1000 |
| `--stress` | сразу включить авто-перерисовку | выкл |
| `--stress-interval MS` | период авто-перерисовки | 500 |
| `--duration SEC` | автостоп и печать отчёта (3600 = час) | 0 (до закрытия окна) |
| `--log-dir DIR` | куда писать CSV/JSON/TXT | `logs` |
| `--seed N` | воспроизводимая генерация | случайный |

### VS Code

Всё уже настроено в `.vscode/`:

* `settings.json` — интерпретатор проекта `${workspaceFolder}\.venv\Scripts\python.exe`,
  автоактивация окружения в терминале, рабочая папка терминала;
* `launch.json` — 7 конфигураций **F5** (лаунчер, каждое из трёх приложений,
  часовой тест, smoke-тесты, headless soak), в каждой явно указан python из `.venv`.

Если папки `.venv` нет (первый запуск на другой машине):

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Дальше: открыть папку в VS Code → **F5** → выбрать, например,
«2 · PyQt6 + QtAgg». Новый встроенный терминал сам активирует `.venv`,
поэтому `python run.py` в нём тоже работает.

Если в терминале `python` всё равно «не распознан» — VS Code его не активировал;
используйте `.\.venv\Scripts\python.exe run.py` или `start.cmd`.

## 4. Как гарантируется «линия не вылезает за рамку»

Четыре независимых уровня — если сломается один, сработают остальные:

1. **Axes не может выйти за Figure.** Оси создаются не через `plt.subplots()`, а
   через `fig.add_axes([0.085, 0.115, 0.895, 0.855])` — прямоугольник внутри
   области рисунка по определению.
2. **Canvas не может стать больше рамки.**
   * Tk: `canvas.place(x=2, y=2, relwidth=1, relheight=1, width=-4, height=-4)` —
     размер всегда «родитель минус 2 px с каждой стороны», менеджер геометрии
     не может его растянуть;
   * Qt: `QFrame#plotFrame` + `QVBoxLayout` с полями 2 px (Qt клиппит детей по
     родителю по умолчанию);
   * wx: `wx.Panel` с `wx.SIMPLE_BORDER` + `wx.BoxSizer(wx.EXPAND)`.
3. **Matplotlib-клиппинг включён явно** и подтверждается на каждом кадре:
   `line.set_clip_on(True)`, `line.set_clip_path(ax.patch)`, `line.set_clip_box(ax.bbox)`
   (`core/view_utils.enforce_clipping`).
4. **Пределы по Y считаются из видимого среза** данных + 6 % отступа
   (`PlotModel.payload`), а `check_bounds()` на каждом кадре численно проверяет,
   что ни одна точка не вышла за `(xlim, ylim)`. Счётчик попадает в отчёт
   («Нарушений клипа: 0»).

Дополнительно зум не может «уехать» за данные: окно прижимается к массиву, а
минимальная ширина окна — 64 точки.

## 5. Тест на утечки памяти (1 час)

Идея: за час сделать десятки тысяч кадров и убедиться, что RSS не растёт.

Что сделано, чтобы память не росла:

| Риск | Решение |
|---|---|
| Новые `Line2D`/тексты на каждый кадр | Объект линии создаётся **один раз**, обновление — `line.set_data()` |
| Накопление массивов данных | Массив фиксированной длины создаётся заново, старый уходит в GC |
| Рост истории замеров | `deque(maxlen=7200)` — ровно 2 часа при интервале 1 с |
| Утечка подписок на сигналы | `Signal.clear()` + `closeEvent`/`EVT_CLOSE`/`protocol(WM_DELETE_WINDOW)` |
| «Висящие» таймеры | `after_cancel` / `QTimer.stop` / `wx.Timer.Stop` при закрытии |
| Рост журнала в Text-виджете | Tk: обрезка до 600 строк; Qt: `setMaximumBlockCount(600)`; wx: обрезка по 60 000 символов |
| Не освобождённая Figure | `fig.clear()` перед `destroy()` |

Что измеряется каждую секунду (`psutil`):

* RSS и VMS процесса, число потоков;
* занятость системной RAM и доступный объём;
* время последнего кадра, p50/p95/макс по всем кадрам;
* нарушения клиппинга.

Главная тонкость: за первые 20–60 секунд процесс набирает RSS — импорт модулей,
кэш шрифтов Matplotlib, буферы canvas, пулы аллокатора. Если считать МНК по всей
сессии, этот «ступенчатый» рост превращается в ложные 30–60 МБ/час и отчёт
объявляет утечку там, где её нет. Поэтому:

* **тренд считается по хвосту сессии**, первые 60 с прогрева исключены;
* отдельно печатается «прогрев» (сколько МБ набралось на старте) и
  «Δ после прогрева» — именно вторая цифра отвечает на вопрос об утечке;
* тренд признаётся надёжным только при ≥ 10 замерах и ≥ 60 с в хвосте,
  иначе вердикт — «мало данных», а не «утечка».

### Как читать отчёт

| Строка | Норма | Тревога |
|---|---|---|
| Δ RSS после прогрева | < 5 МБ — шум | ≥ 5 МБ и тренд ≥ 2 МБ/час — «внимание», ≥ 8 МБ/час или ≥ 60 МБ — «утечка» |
| p95 кадра | < 150 мс | ≥ 150 — предупреждение, ≥ 400 — дефект |
| Нарушений клипа | 0 | любое > 0 — дефект |

Порог в 5 МБ нужен потому, что доли мегабайта за пару минут — это шум
аллокатора; экстраполяция такого шума на час даёт «+25 МБ/час» и ложную
тревогу. Поэтому в таблице сравнения вместо такого числа стоит `≈0`.

Пороги вынесены в начало `gcompare/core/diagnostics.py`.

Файлы сессии:

```
logs/tkinter_20261117_081500.csv          # замеры, 1 строка/сек
logs/tkinter_20261117_081500_report.txt   # тот самый текстовый отчёт
logs/tkinter_20261117_081500_summary.json # сводка для сравнения
logs/comparison.md                        # таблица по трём библиотекам
```

## 6. Архитектура

```
run.py                     лаунчер (Tk) + CLI: --app / --compare
gcompare/
  registry.py              метаданные приложений, команда запуска
  launcher_tk.py           окно лаунчера
  core/                    ← НЕ зависит ни от одной GUI-библиотеки
    signals.py             Signal/Slot (connect / emit / disconnect / clear)
    data.py                генераторы Random / Meander / Saw
    model.py               PlotModel: данные + окно зума + пределы осей
    view_utils.py          клиппинг, проверка границ, оформление осей, rcParams
    metrics.py             MemoryProbe: RSS, RAM, тренд МБ/час
    diagnostics.py         события, тайминги кадров, текст отчёта и вердикт
    session.py             SessionController — шина «модель ↔ GUI ↔ метрики»
    session_log.py         CSV / JSON / TXT
    theme.py               палитра и подписи (одинаковые во всех трёх окнах)
  apps/
    tk_app.py              Tkinter + FigureCanvasTkAgg
    qt_app.py              PyQt6   + FigureCanvasQTAgg
    wx_app.py              wxPython+ FigureCanvasWxAgg
tools/
  smoke_test.py            7 проверок ядра (+ --gui: пробный запуск окон)
  soak_test.py             headless-прогон того же кадрового конвейера на Agg
```

Поток событий (Slot/Signal):

```
[кнопка] ──emit──► AppSignals.show_graph ──► SessionController.show_graph()
                                                   │
                                    PlotModel.generate() ── data_changed
                                                   │
                                            render_request(payload)
                                                   ▼
                                   canvas: set_data → set_xlim/ylim → draw()
                                                   │
                                   record_render(ms, points, violations)
                                                   ▼
                              Diagnostics → память/отчёт → панель и logs/
```

* В Tkinter и wxPython «сигналы» — свой класс `core/signals.Signal`
  (нативных нет). Кнопки используют `command=` / `Bind(EVT_BUTTON)` и только
  `emit`-ят событие.
* В PyQt6 — нативные `pyqtSignal`/`@pyqtSlot`; шина контроллера транслируется в
  них через объект-мост `Bridge`, поэтому логика не знает про Qt.
* Все три окна подключаются к **одному и тому же** контроллеру, поэтому
  поведение идентично, а различия — только в виджетах.

## 7. Сравнение библиотек

| | Tkinter | PyQt6 | wxPython |
|---|---|---|---|
| Установка | входит в Python | `pip install PyQt6` (~90 МБ) | `pip install wxPython` (~20 МБ) |
| Лицензия | PSF | GPL v3 / коммерческая | wxWindows (LGPL) |
| Внешний вид | свой, аскетичный | рисует сам, одинаково на всех ОС | нативные контролы ОС |
| HiDPI | вручную | из коробки | из коробки (4.2+) |
| Сигналы | нет (свои) | `pyqtSignal` | `Bind` |
| Раскладка | grid/pack/place | layout-менеджеры | sizer'ы |
| Интеграция с Matplotlib | `backend_tkagg` | `backend_qtagg` | `backend_wxagg` |
| Когда выбирать | утилита «здесь и сейчас», без зависимостей | сложный UI, тёмная тема, графики, анимации | корпоративный десктоп с нативным видом |

Замеры на этой машине (Python 3.12.2, Matplotlib 3.11.2, окно 1280×780,
4096 точек на кадр, canvas ~860×710):

| | p95 кадра | RSS: старт → конец | Δ после прогрева |
|---|---|---|---|
| Tkinter | 58 мс | 75 → 96 МБ | +0.0 МБ |
| PyQt6 | 49 мс | 106 → 132 МБ | +0.1 МБ |
| wxPython | 52 мс | 88 → 103 МБ | +0.5 МБ |

Сессия 2.5 минуты, 480 кадров, стресс-тест каждые 300 мс, окно 1280×780,
4096 точек на кадр. Полные логи — в `logs/`, сводка — `logs/comparison.md`.

Разница в скорости отрисовки между бэкендами в пределах погрешности — узкое место
у всех одно и то же, сам Agg-рендерер Matplotlib. Разница в памяти — это стоимость
Qt-библиотек и кэшей wx.

> Значения зависят от машины: запустите `python run.py --app all --duration 600`
> и `python run.py --compare`, чтобы получить свои.

## 9. Известные ограничения

* Скорость кадра определяется Matplotlib: на 4096 точках ~40–50 мс на кадр
  (≈20 FPS). Для плавной анимации нужен blitting или меньшее число точек
  (`--points 1024` → ~20 мс).
* wxPython и PyQt6 держат внутренние кэши: за первые секунды RSS прибавляет
  10–40 МБ, затем выходит на плато. Поэтому отчёт и просит прогон ≥ 5 минут,
  а честный вывод об утечке делает после часа.
* Сравнение корректно только при одинаковых `--points` и размере окна.
* `--duration` закрывает окно принудительно и печатает отчёт в консоль; если
  запускать из лаунчера, консоль дочернего процесса закроется вместе с ним —
  отчёт остаётся в `logs/`.
